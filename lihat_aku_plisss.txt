================================================================================
BUKU PANDUAN OPERASIONAL & ARSITEKTUR SISTEM (MODELLYNG WEB)
Evidence-Centered Academic PDF Analysis Platform
================================================================================

Dokumen ini merupakan panduan operasional resmi untuk menjalankan, mengelola,
dan mengembangkan seluruh ekosistem Modellyng Web (Frontend, Backend API,
Antrean Tugas Celery, Basis Data Supabase PostgreSQL, dan Redis).

================================================================================
PANDUAN INSTALASI & MENJALANKAN PROYEK PERTAMA KALI (CLONE DARI GITHUB)
================================================================================

Ikuti langkah-langkah di bawah ini secara runtut saat baru pertama kali menyalin
repositori ke komputer atau laptop:

--------------------------------------------------------------------------------
PRASYARAT PERANGKAT LUNAK (WAJIB TERPASANG)
--------------------------------------------------------------------------------
Pastikan aplikasi berikut sudah terpasang pada sistem operasi:
1. Git: Memeriksa instalasi di terminal -> `git --version`
2. Node.js (Versi 18 atau 20 LTS disarankan): Memeriksa instalasi -> `node -v`
3. Python (Versi 3.10 atau lebih baru): Memeriksa instalasi -> `python --version`
4. Docker Desktop: Pastikan aplikasi Docker Desktop sudah terpasang dan dalam status berjalan (*Engine running*).
5. Peramban Web Modern: Google Chrome, Microsoft Edge, Brave, atau Mozilla Firefox.


--------------------------------------------------------------------------------
LANGKAH 1: MENGUNDUH (CLONE) REPOSITORI DARI GITHUB
--------------------------------------------------------------------------------
1. Buka aplikasi Terminal (PowerShell, Command Prompt, atau Git Bash).
2. Jalankan perintah untuk mengunduh kode proyek:
   git clone https://github.com/Extluke/Modellying-web.git

3. Masuk ke folder utama proyek:
   cd Modellying-web


--------------------------------------------------------------------------------
LANGKAH 2: PENYIAPAN BERKAS KONFIGURASI ENVIRONMENT (.env)
--------------------------------------------------------------------------------
Layanan backend membutuhkan konfigurasi koneksi basis data, Redis, dan kunci API AI.

1. Periksa keberadaan berkas `modellyng/backend/.env`.
2. Jika belum ada, buat berkas baru dengan nama `.env` di folder `modellyng/backend/`.

DETAIL FITUR & INTEGRASI SISTEM
================================================================================

1. INTEGRASI FASTAPI & BASIS DATA SUPABASE POSTGRESQL
--------------------------------------------------------------------------------
- Backend menggunakan koneksi pool aman (`psycopg2-binary` dengan `ThreadedConnectionPool`).
- Seluruh registrasi akun baru dienkripsi menggunakan standar keamanan militer Argon2id.
- Skema tabel relasional meliputi:
  * `public.users`: Manajemen identitas, nama, email, dan hash sandi pengguna.
  * `public.projects`: Judul penelitian, rumusan masalah, bidang riset, dan format sitasi.
  * `public.papers`: Metadata dokumen PDF (judul, pengarang, tahun, hash SHA-256, jumlah halaman, dan status proses).
  * `public.extracted_components`: Hasil ekstraksi 11 parameter dalam format JSONB dinamis.
  * `public.paper_blocks`: Koordinat bounding box dan segmen teks per halaman untuk highlighter bukti PDF.
  * `public.password_reset_tokens`: Pengelolaan token unik pemulihan kata sandi dengan masa kedaluwarsa 1 jam.
  * `public.subscription_plans`: Katalog paket langganan mahasiswa (`free`, `student_14`, `student_30`) memuat harga IDR, durasi hari, limit berkas harian, limit token harian, dan fitur JSONB.
  * `public.user_subscriptions`: Relasi langganan pengguna aktif, masa aktif, relasi invoice, dan total token terakumulasi.
  * `public.user_daily_usage`: Buku kas kuota harian (*daily usage ledger*) berkonstrain unik `(user_id, usage_date)` untuk tracking konsumsi 3 file/hari (Free) dan 15 token/hari (Student Pro).
  * `public.subscription_invoices`: Riwayat transaksi dan tagihan dengan nomor invoice unik, nominal IDR, metode pembayaran (QRIS/VA), dan status verifikasi.
  * `public.v_user_active_subscription`: View analitik status paket aktif pengguna saat ini beserta perhitungan sisa hari dan batas kuota.

4. PIPELINE EKSTRAKSI PDF ASINKRON (CELERY WORKER & REDIS)
--------------------------------------------------------------------------------
- Alur Pemrosesan 10 Tahap Idempoten:
  `queued` -> `downloading` -> `extracting_text` -> `quality_check` ->
  `doc_type_check` -> `saving_blocks` -> `ai_extraction` -> `verifying_evidence` ->
  `saving_ai_results` -> `ai_extraction_complete`.
- Validasi Magic Bytes:
  Memverifikasi penanda biner asli `%PDF-` untuk mencegah pengunggahan file rusak atau palsu.
- Deteksi Duplikasi Cerdas & Manajemen Berkas:
  Menggunakan enkripsi hash SHA-256 untuk mendeteksi dokumen identik dalam satu proyek (`duplicate_content`).
  Pesan error kini secara spesifik mencantumkan judul asli paper yang berkonflik.
  Jika paper yang pernah diunggah sebelumnya berstatus gagal (`failed`), sistem secara otomatis
  membersihkan entri lama dan mengizinkan pengunggahan ulang berkas yang sama tanpa terblokir.
  Penghapusan proyek (`DELETE /projects/:id`) membersihkan rekaman basis data (kaskade) serta
  seluruh file PDF fisik di dalam direktori `STORAGE_ROOT/{user_id}/{project_id}`.
- Ekstraksi Judul Asli & Penulis Paper Otomatis (Anti-Judul Semrawut):
  * Tahap Cepat saat Upload (Fast Heuristic): Fungsi `inspect_pdf_metadata` menyaring dan membuang
    metadata rusak bawaan template penerbit/Word (seperti `Author,+Information...`, `7952_2`, atau UUID).
    Sistem menganalisis ukuran font terbesar pada halaman pertama (excluding journal headers)
    sehingga judul asli langsung rapi sejak detik pertama diunggah, terbebas dari nama file sembarang.
  * Tahap Penyempurnaan AI (Stage 5 Celery): Model LLM (`openai/gpt-oss-120b`, `openai/gpt-oss-20b`,
    `qwen/qwen3.8-27b`) mengekstrak judul penelitian akademik yang bersih serta array nama pengarang
    (`authors`), lalu menyimpannya ke tabel `public.papers`.
- Arsitektur Abstraksi Model AI Terpadu (ModelRegistry — Gemini Core & Groq Backup):
  * Dual-Provider Resilient Architecture:
    1. Model Utama (Core Provider): Google Gemini (`models/gemini-3.5-flash`), dioptimalkan untuk sintesis ilmiah Bahasa Indonesia baku dan ekstraksi terstruktur.
    2. Model Cadangan (Backup Provider): Groq (`qwen/qwen3.8-27b` / `openai/gpt-oss-120b`), siap mengambil alih tugas seketika jika model utama mengalami kendala kuota.
  * Mekanisme Token Bucket Rate Limiting & Micro-Retry:
    - Pembatas laju independen sadar RPM dan TPM (`gemini_limiter` & `groq_limiter`) yang mencegah banjir request 429.
    - Micro-retry per model hingga maksimal 2 kali retry (total 3x percobaan per model) dengan jeda eksponensial (*exponential backoff* dan jitter).
    - Kegagalan total pada Core Model otomatis memicu pengalihan tugas (*seamless failover*) ke Backup Model tanpa memutus atau mengulang batch tugas yang sudah berhasil.
  * Validasi Skema Pydantic Ketat & Log Bersih (Sanitized Logging):
    - Seluruh respons LLM divalidasi secara ketat oleh skema Pydantic; data yang tidak lolos validasi tidak akan pernah masuk ke basis data.
    - Log sistem hanya mencatat metadata, model alias, dan waktu eksekusi; teks mentah naskah pengguna dilarang keras dicetak pada log.
- Gatekeeper LLM & Kebijakan Penerjemahan Baku (Indonesian First Extraction):
  * Mendeteksi apakah dokumen merupakan artikel ilmiah valid atau sekadar naskah non-paper.
  * System prompt mewajibkan seluruh nilai ekstraksi ilmiah (`value.text`) diterjemahkan dan diformulasikan ke dalam Bahasa Indonesia yang baku, elegan, dan akademis.
  * Kutipan bukti verbatim (`evidence.quote`) tetap dipertahankan dalam bahasa asli naskah PDF demi menjamin ketertelusuran fisik kanonik (*ground truth*).
- Sinkronisasi UI Cerdas (Smart Polling):
  TanStack Query pada frontend otomatis memantau status pemrosesan setiap 3 detik selama ada
  tugas aktif (`validating` / `processing`), dan otomatis berhenti saat status menjadi `ready` atau `needs_review`.

6. PENCARIAN HIBRIDA POSTGRESQL & MESIN OBROLAN TANYA AI (ANTI-HALUSINASI)
--------------------------------------------------------------------------------
- Algoritma Pencarian Hibrida PostgreSQL & Reciprocal Rank Fusion (RRF):
  * Mengombinasikan pencarian semantik padat (dense retrieval) via pgvector indeks HNSW
    (`public.paper_embeddings` dengan operator jarak kosinus `<=>`) dan pencarian kata kunci
    eksak (sparse lexical retrieval) via Full-Text Search bawaan PostgreSQL (kolom
    `paper_blocks.fts_tokens` berindeks GIN dengan fungsi `to_tsvector` dan `plainto_tsquery`).
  * Mengintegrasikan algoritma fusi Reciprocal Rank Fusion (RRF dengan parameter konstanta k=60):
    RRF_Score(d) = SUM( 1 / (60 + rank_semantik) + 1 / (60 + rank_bm25) )
  * Menyaring 5 hingga 7 blok teks teratas dengan relevansi tertinggi untuk diinjeksikan
    sebagai konteks primer ke System Prompt LLM.
- Validasi Anti-Halusinasi & Structured Outputs LLM:
  * System prompt menginstruksikan LLM (Groq Llama 3.3 70B atau Gemini 1.5 Flash) bekerja
    dalam mode Structured Outputs (Pydantic / JSON Mode).
  * Menghasilkan dua objek terstruktur: `answer` (teks balasan berformat Markdown kaya) dan
    `citations` (array sitasi kanonik berisi ID blok teks, judul paper, nomor halaman fisik,
    dan koordinat bounding box [x0, y0, x1, y1]).
  * Kebijakan Nol Halusinasi: Jika informasi yang ditanyakan tidak tercantum dalam konteks
    hasil RRF, sistem wajib membalas secara eksplisit: "Informasi tidak ditemukan dalam
    dokumen proyek ini".

      daftar dokumen paper pendukung beserta penulis dan tahun terbit, serta kutipan bukti verbatim (*verbatim quote*)
      lengkap dengan nomor halaman kanonik.
    - Tombol aksi: "Jadikan Fokus Novelty Tesis" dan "Salin Ringkasan Simpul" dengan toast feedback standar 5 detik (5000 ms).
  * Kartu Rekomendasi Aksi Strategis 4 Tahap (`FourStageActionCard.tsx`):
    - Grid responsif 4 kolom yang memandu tindakan taktis akademis:
      1. Tahap 1 (Topik): Penyelarasan batasan ruang lingkup penelitian.
      2. Tahap 2 (Tema): Konsolidasi landasan teoretis pada tema bersama (hijau).
      3. Tahap 3 (Masalah): Eksplorasi akar kontradiksi masalah kritis.
      4. Tahap 4 (Solusi): Eksploitasi peluang novelty pada simpul merah (solusi langka) vs validasi pada simpul hijau.
12. FITUR PETA KONSEPSI RISET & PERBANDINGAN BERPASANGAN 5 TAHAP (CONCEPT MAP & PAIRWISE ENGINE)
--------------------------------------------------------------------------------
- Pusat Ruang Kerja Peta Konsepsi & Celah Riset (`ConceptMapScreen.tsx` pada rute `/concept-map` dan `/projects/:projectId/concept-map`):
  * Pengendali Rute Ganda (Dual Route Dispatcher): Mendukung resolusi ID proyek melalui parameter rute maupun URL search param (`/concept-map?projectId=...`).
  * Validasi Kesiapan Akademis (>= 2 Paper Siap): Mengelompokkan proyek berdasarkan jumlah naskah ilmiah siap analisis.
    Bila proyek memiliki kurang dari 2 paper siap, disajikan callout amber solutif dengan tautan langsung ke halaman unggah paper.
  * Dasbor Statistik Agregat: Metrik Total Pasangan Ilmiah (N * (N - 1) / 2), Kandidat Celah Riset Terdeteksi,
    Keterbatasan Terpetakan, dan Celah Layak Diteliti (Accepted).

- Mesin Komparasi Berpasangan Terurut 5 Tahap (5-Step Deterministic Stopping Rule):
  * Menganalisis seluruh permutasi pasangan naskah akademik secara berpasangan dengan 5 tahap uji deterministik berurutan:
    1. Tahap 1 (Konsep Utama): Apakah kedua naskah meneliti konsep/domain teoretis yang sama? Jika tidak, berhenti sebagai Unrelated.
    2. Tahap 2 (Variabel Penelitian): Apakah variabel independen/dependen/mediasi identik? Jika tidak, berhenti sebagai Candidate Gap (Variables).
    3. Tahap 3 (Objek / Dataset): Apakah objek populasi atau domain data setara? Jika tidak, berhenti sebagai Candidate Gap (Population/Dataset).
    4. Tahap 4 (Metodologi): Apakah metodologi atau algoritma pengolahan setara? Jika tidak, berhenti sebagai Candidate Gap (Methodology).
    5. Tahap 5 (Cakupan Masalah): Apakah batasan masalah ilmiah identik? Jika tidak, berhenti sebagai Candidate Gap (Problem Scope); bila seluruh aspek identik, berstatus No Gap.
  * Setiap langkah pengujian dilengkapi kutipan bukti empiris (verbatim evidence quote) dari naskah beserta nomor halaman kanonik.

- Kanvas Visual Rantai Keterbatasan & Peluang Masa Depan (`LimitationsFutureWorkCanvas.tsx`):
  * Berbasis `@xyflow/react` dengan kanvas interaktif (pan, zoom, minimap, background dots).
  * Alur rantai kausalitas horizontal terstruktur:
    Node Paper Sumber (Biru) -> Keterbatasan Naskah/Limitation (Kuning Emas) -> Peluang Riset/Future Work (Indigo) -> Celah Kebaruan/Novelty Gap (Hijau Emerald).
  * Menghubungkan secara eksplisit poin keterbatasan yang diakui oleh penulis naskah terdahulu langsung ke agenda peluang masa depan yang dapat dieksploitasi untuk tesis.

- Visualisasi Diagram Alur Keputusan Mermaid Dinamis (`FiveStepMermaidFlowchart.tsx`):
  * Ditenagai oleh pustaka `mermaid` v12.2.0 terisolasi dalam vendor chunk khusus (`vendor-mermaid`).
  * Menghasilkan representasi diagram alur `graph TD` interaktif dengan simbol wajik (decision diamonds) dan pewarnaan CSS Modellyng Academic.
  * Fitur salin kode sintesis Mermaid dan sakelar mode "Lihat Kode Mermaid" dengan konfirmasi notifikasi seragam 5000 ms.

- Polling Sinkronisasi Otomatis 5 Detik (`PairwiseComparisonPanel.tsx` & `ProjectConceptMapView.tsx`):
  * Siklus polling berkala 5 detik terukur dengan indikator penghitung mundur (countdown timer) dan status denyut nadi (pulse indicator).
  * Memperbarui matriks dan status pasangan paper secara mulus di latar belakang tanpa menginterupsi interaksi pengguna.

- Hub Validasi Keputusan Reviewer Celah Riset (`GapDecisionModal.tsx` & `GapCandidateCard.tsx`):
  * Menampilkan kartu kandidat celah riset lengkap dengan kategori celah, domain ilmiah, akar masalah (core issue), rekomendasi solusi pengganti, dan usulan judul tesis.
  * Modal peninjauan interaktif untuk memberikan keputusan validasi: "Layak Diteliti (Accept)" atau "Ditolak / Duplikasi (Reject)".
  * Kolom catatan ilmiah reviewer untuk justifikasi akademik dengan umpan balik toast seragam tepat 5000 ms.
13. FITUR ASISTEN CERDAS GLOBAL & AUTOCOMPLETE KONTEKS (GLOBAL CHAT & CONTEXT TAGGING)
--------------------------------------------------------------------------------
- Layar Utama Asisten Cerdas Global (`ChatGlobalScreen.tsx` pada rute `/chat`):
  * Titik temu asisten kecerdasan buatan universal untuk eksplorasi literatur lintas-dokumen,
    konsultasi metodologi riset, dan investigasi temuan naskah berbasis bukti (*evidence-centered*).
  * Arsitektur Dual-Mode Chat (Pemisahan Mode Konteks Tertaut & Mode Universal Global):
    - **Mode Konteks Tertaut (*Scoped Mode*):** Aktif saat pengguna menyematkan tag `@proyek` atau `/paper`.
      Kueri dikirim ke `POST /api/v1/projects/{project_id}/chat` untuk mendapatkan analisis mendalam berbasis
      bukti kutipan naskah dokumen fisik (*evidence quotes* `[S1]`, `[S2]`).
    - **Mode Asisten Universal (*Unscoped Global Mode*):** Aktif saat tidak ada tag `@proyek` yang dipilih.
      Kueri dikirim ke endpoint baru `POST /api/v1/projects/chat/global` tanpa mengunci diri pada satu proyek
      manapun secara sepihak (menghapus fallback otomatis `projects[0]`).
  * Kemampuan Penalaran Percakapan Multi-Turn ("Bisa Diajak Diskusi"):
    - Menghilangkan balasan kaku "Informasi tidak ditemukan" pada sapaan santai ("halo", "hai") maupun
      pertanyaan umum konseptual. Asisten merespons secara ramah dan profesional sebagai rekan diskusi akademik.
    - Menjaga konteks percakapan multi-turn: riwayat percakapan sebelumnya (`history` 6 putaran terakhir)
      diteruskan ke backend RAG sehingga asisten memahami rujukan kata ganti (misal: "paper tersebut membahas apa?",
      "jelaskan metodologinya lebih detail").
  * Sintesis Lintas Dokumen & Komparasi Multi-Paper Otomatis:
    - Saat ditanyakan cakupan proyek (misal: "project ini membahas apa?"), asisten melakukan sintesis tingkat tinggi
      yang merangkum seluruh paper yang ada di dalam proyek secara komprehensif, mencakup rumusan masalah,
      metodologi yang dipakai, temuan empiris, dan celah penelitian.
  * Terhubung secara mulus dengan tombol "Asisten Global" pada bilah navigasi atas (`Header.tsx`).

- Integrasi Backend RAG Cerdas & Manajemen Token (`rag_service.py` & `hybrid_search.py`):
  * Mesin LLM Groq Terkelola: Menggunakan model akademik cerdas `qwen/qwen3.8-27b` (atau fallback konfigurabel via `GROQ_MODEL_NAME`).
  * Injeksi Metadata Proyek Otomatis: Ringkasan naskah (judul, penulis, tahun, rumusan, metodologi, temuan)
    diinjeksikan langsung ke prompt sistem sehingga asisten selalu memahami gambaran utuh proyek tanpa bergantung
    pada kecocokan kata kunci mentah (*lexical keyword overlap*).
  * Pencarian Hibrida Dense & Sparse dengan Filter Paper: Mendukung pemfilteran spesifik naskah (`paper_id`)
    saat chip `/paper` aktif, serta fallback blok dasar (halaman 1-2) jika query bersifat umum agar konteks tidak kosong.
  * Perlindungan Batas Kuota Token (Token Budgeting): Pemangkasan cuplikan blok (maksimal 4 blok teratas,
    dipotong maksimal 400 karakter per blok) dan riwayat percakapan untuk menjaga utilisasi token di bawah batas
    ketat 7.000 ITPM (Input Tokens Per Minute) Groq.
  * Cadangan Deterministik Cerdas: Jika terjadi gangguan jaringan atau API Groq tidak tersedia, sistem membangkitkan
    respons ringkasan terstruktur berbasis data ekstraksi kanonik tanpa pernah memunculkan pesan gagal buntu.

- Mekanisme Autocomplete Konteks Interaktif (`@proyek` dan `/paper`):
  * Deteksi Kursor Real-Time (`autocompleteParser.ts`):
    - Mengetik simbol `@` memunculkan popover mengambang (`ContextAutocompleteMenu.tsx`) yang memuat
      daftar seluruh proyek riset aktif milik pengguna.
    - Mengetik simbol `/` memunculkan popover yang memuat daftar naskah paper spesifik (otomatis menyaring
      paper di dalam proyek bila `@proyek` telah terpilih).
  * Navigasi Keyboard Penuh:
    - Pengguna dapat bernavigasi menggunakan tombol Panah Bawah (`Down`), Panah Atas (`Up`),
      memilih dengan `Enter` atau `Tab`, serta membatalkan/menutup dengan `Escape` atau tombol `X`.
  * Penyematan Konteks (*Context Chips*):
    - Saat item dipilih, token pemicu pada teks input otomatis dibersihkan dan disematkan sebagai chip
      interaktif beraksen visual di atas input bar (`@NamaProyek` berwarna Indigo, `/JudulPaper` berwarna Emerald).
    - Chip dapat dilepas kapan saja dengan tombol silang `x` tanpa merusak teks pertanyaan yang sedang diketik.

- Desain Kotak Input Responsif & Bebas Scrollbar (`GlobalChatInputBar.tsx`):
  * Pengaturan Tinggi Otomatis (Auto-Grow): Bidang pengetikan meluas secara dinamis mengikuti panjang teks
    pertanyaan hingga batas proporsional 140 px (`max-h-36`).
  * Eliminasi Scrollbar Bawaan Peramban (Clean Aesthetic):
    - Menerapkan utilitas `.no-scrollbar`, `[scrollbar-width:none]`, `[-ms-overflow-style:none]`, serta
      `[&::-webkit-scrollbar]:hidden` sehingga panah scrollbar bawaan sistem operasi (Windows/Edge/Chrome/Firefox)
      tidak pernah muncul mengganggu estetika antarmuka.
    - Kontrol `overflowY` otomatis disetel `hidden` saat teks pendek (1 baris) dan bertransisi mulus ke `auto`
      saat teks melampaui 140 px tanpa memunculkan bilah geser visual.

- Kebijakan Caching Lokal 24 Jam & Pemangkasan Otomatis (*Auto-Prune* via `localStorage`):
  * Sesuai spesifikasi audit fitur Modellyng (Kategori 13), riwayat percakapan asisten global disimpan
    secara privat di sisi klien pengguna (`modellyng_global_chat_history_${userId}`) dengan batas waktu 24 jam.
  * Algoritma Pemangkasan Otomatis (*Auto-Prune*):
    - Setiap kali layar dimuat atau pesan baru ditambahkan, sistem memfilter pesan yang usianya melampaui
      24 jam (`Date.now() - msg.timestamp > 86400000 ms`). Pesan kedaluwarsa otomatis dibuang untuk menjaga efisiensi memori.
  * Penyimpanan Draf Pertanyaan (*Draft Auto-Save*):
    - Teks pertanyaan yang belum terkirim otomatis tersimpan di `localStorage` (`modellyng_global_chat_draft_${userId}`)
      sehingga ketikan pengguna tidak akan pernah hilang saat beralih tab atau me-refresh peramban.
  * Tombol Bersihkan Riwayat Manual & Reset Konteks Total (*Zero-Leakage State Reset*):
    - Tombol "Bersihkan Riwayat" pada bilah atas memunculkan dialog konfirmasi (`ClearHistoryConfirmModal.tsx`).
    - Saat dikonfirmasi, sistem membersihkan seluruh pesan di tampilan (`setMessages([])`), menghapus cache lokal
      (`clearCachedMessages`), memanggil `clearContextScope()` untuk mencopot seluruh chip konteks (`@proyek` dan `/paper`),
      mengosongkan draf ketikan (`clearChatDraft` & `setInputText("")`), serta mereset popover autocomplete dengan
      umpan balik toast seragam 5000 ms.
    - Menjamin bahwa obrolan berikutnya dimulai dari kondisi bersih (*fresh universal state*) tanpa ada konteks
      yang tertinggal atau bocor dari percakapan sebelumnya.

- Perenderan Respon Kaya Markdown & Sitasi Naskah Interaktif (`GlobalChatMessageItem.tsx`):
  * Ditenagai oleh `react-markdown` dan `remark-gfm` untuk memformat heading, bullet points, tabel komparasi,
    blok kutipan, dan cuplikan kode secara estetis sesuai standar tipografi Modellyng.
  * Tautan Rujukan Sitasi Naskah `[S#]`:
    - Simbol sitasi (misal: `[S1]`, `[S2]`) diproses menjadi tombol interaktif yang bila diklik akan membuka
      modal pratinjau bukti naskah (`CitationPreviewModal.tsx`), menampilkan judul paper, nomor halaman kanonik,
      dan kutipan teks asli (*verbatim quote*) yang dapat disalin ke papan klip.
  * Tombol Salin Jawaban: Ikon salin yang muncul pada balon pesan asisten memudahkan pengguna menyalin teks formulasi
    ilmiah ke draf naskah tesis.

- Optimalisasi Kuota Token & Mekanisme Pemulihan Draf (*Error Recovery*):
  * Pembatasan Riwayat Pengiriman: Hanya mengirim maksimal 6 pesan riwayat terakhir dengan batas maksimal 1500
    karakter per pesan untuk menghemat window token LLM.
  * Mekanisme Retry Otomatis 1 Kali: Menangani gangguan koneksi sesaat atau lonjakan beban server.
  * Pemulihan Draf Saat Gagal Jaringan: Jika koneksi gagal total, sistem otomatis mengembalikan teks pertanyaan
    ke dalam kolom input agar pengguna tidak kehilangan draf ketikan panjangnya, disertai pesan toast peringatan 5000 ms.

14. FITUR GRAF PENGETAHUAN (KNOWLEDGE GRAPH) & ZONA SATURASI
--------------------------------------------------------------------------------
- Pusat Pemilihan Proyek (`KnowledgeGraphScreen.tsx` pada rute `/knowledge-graph`):
  * Katalog proyek dengan syarat >= 2 paper siap. Proyek yang belum siap menampilkan callout amber dan tautan unggah paper.
  * Tombol "Buka Graf Pengetahuan" membuka rute fokus `/projects/:projectId/knowledge-graph`
    (`ProjectKnowledgeGraphScreen.tsx`, tanpa sidebar dan navbar). Tautan lama `/knowledge-graph?projectId=<id>` dialihkan otomatis.

- Pembangun Graf (`utils/graphBuilder.ts`), mengikuti model data aplikasi mobile:
  * Sumber data: `GET /api/v1/projects/{id}/comparative-matrix`. Hanya paper berstatus Siap atau Perlu Tinjauan yang ditampilkan.
  * Jenis simpul: Paper, Bidang Riset (rumusan masalah), Konsep (variabel & konsep), Dataset/Objek, Metode, Hasil, dan Celah Riset
    (keterbatasan & peluang riset mendatang). Judul simpul adalah potongan teks asli sel ekstraksi tanpa kalimat pembuka baku
    (`graphText.ts`); uraian lengkap dan bukti kutipan tetap tersedia pada panel rincian.
  * Relasi: paper -> bidang riset/konsep ("meneliti"), paper -> dataset/metode ("menggunakan"), metode -> hasil ("menghasilkan"),
    hasil -> celah ("mengungkap"). Gagasan identik dari beberapa paper digabung menjadi satu simpul bersama.
  * Keterhubungan antar paper: simpul sejenis dengan kata kunci bersama dihubungkan garis putus-putus "Serupa antar paper".
    Bila graf masih terpisah, kelompok digabung lewat pasangan simpul paling mirip (minimal 2 kata kunci bersama).
    Lencana pada kartu judul menampilkan "Terhubung utuh" atau jumlah kelompok terpisah.
  * Saturasi = porsi paper yang membahas simpul: <= 20% Rendah, <= 50% Sedang, selebihnya Tinggi. Celah Riset selalu zona
    "Celah Riset"; paper berada pada zona "Sumber Paper".

- Tata Letak Zona (`utils/graphLayout.ts`): zona berurutan dari kiri ke kanan: Sumber Paper | Saturasi Tinggi | Sedang | Rendah |
  Celah Riset. Simpul dalam zona disusun dalam kolom dan diurutkan menurut rata-rata posisi tetangganya untuk memperpendek garis.

- Kanvas (`KnowledgeGraphCanvas.tsx`, React Flow dimuat lazy bersama rute):
  * Kartu simpul bergradasi per jenis (`KnowledgeGraphNodeCard.tsx`) dan garis melayang yang keluar dari tepi kartu (`FloatingEdge.tsx`).
  * Toolbar di kiri atas: perbesar, perkecil, tampilkan seluruh graf, atur ulang tata letak, dan layar penuh (Esc untuk keluar).
  * Menyorot simpul (arahkan kursor atau pilih) menonjolkan simpul dan tetangganya; sisanya diredupkan. Mini-map dan legenda tersedia.
  * Pencarian teks, filter zona, dan filter jenis simpul meredupkan simpul yang tidak sesuai.
  * Saat simpul dipilih, kanvas bergeser secukupnya agar simpul dan tetangganya tidak tertutup panel rincian.

- Panel Rincian (`NodeDetailPanel.tsx`): jenis dan uraian simpul, zona, cakupan paper, tipologi celah, skor keyakinan, paper pelapor,
  bukti kutipan (tombol "Lihat di PDF"), daftar simpul terhubung, dan tombol "Salin Ringkasan".
  * "Lihat di PDF" membuka `projects/paper-analysis/EvidencePdfModal.tsx` (dimuat lazy, memuat pdf.js). Penampil mengambil blok
    kanonik paper, memverifikasi blok yang dicatat terhadap teks kutipan, mencari halaman yang benar bila catatan keliru,
    lalu menggulir dan menyorot kutipan.

- Sintesis Rumusan Masalah (AI): pada simpul Celah Riset, tombol "Buat Rumusan Masalah (AI)" mengirim celah beserta hasil/metode
  asalnya ke `POST /api/v1/projects/{id}/knowledge-graph/synthesize` (`graph_synthesis_service.py`, ModelRegistry Gemini -> Groq).
  Hasilnya (3 usulan judul, 2-3 pertanyaan penelitian, pernyataan novelty, alasan pemilihan) tampil pada
  `SynthesisResultDialog.tsx` sebagai draf yang wajib ditinjau pengguna. Bila semua model gagal, pengguna menerima pesan galat
  (HTTP 503) dan tidak ada teks pengganti yang dikarang.

- Keterbatasan saat ini: simpul diturunkan dari teks sel ekstraksi, bukan dari ekstraksi entitas khusus seperti pada aplikasi mobile,
  sehingga pada proyek kecil sebagian besar simpul hanya dilaporkan oleh satu paper dan berada pada satu zona saturasi.

================================================================================
CATATAN TEKNIS & PEMECAHAN MASALAH (TROUBLESHOOTING)
================================================================================

1. PORT 3000 ATAU 8000 SEDANG DIGUNAKAN (PORT IN USE)
--------------------------------------------------------------------------------
- Jika port 3000 sedang terpakai oleh aplikasi lain, Vite secara otomatis akan berpindah
  ke port berikutnya (misalnya: `http://localhost:3001/`). Perhatikan alamat URL yang
  ditampilkan pada terminal.
- Jika port 8000 terpakai, Anda dapat menghentikan proses lama atau menentukan port lain
  pada perintah uvicorn dengan mengganti `--port 8000` menjadi `--port 8008`. Pastikan
  untuk menyesuaikan variabel `VITE_API_BASE_URL` di frontend jika mengubah port backend.

2. EKSEKUSI CELERY WORKER DI SISTEM OPERASI WINDOWS
--------------------------------------------------------------------------------
Sistem operasi Windows tidak mendukung mekanisme multiprocessing default Celery (fork).
Oleh karena itu, selalu gunakan argumen `--pool=solo`:
  celery -A app.celery_app worker --loglevel=info --pool=solo

3. DOCKER DESKTOP BELUM AKTIF ATAU GAGAL TERHUBUNG
--------------------------------------------------------------------------------
- Pastikan aplikasi Docker Desktop sudah dibuka sebelum menjalankan `docker compose up -d`.
- Jika kontainer gagal menyala karena konflik port, pastikan port `28022` dan `6381` tidak
  digunakan oleh aplikasi basis data lain di komputer Anda.
- Untuk mereset kontainer Docker ke kondisi bersih:
  cd modellyng/backend/docker
  docker compose down
  docker compose up -d

4. VERIFIKASI KETEPATAN TIPE DATA (TYPECHECK FRONTEND)
--------------------------------------------------------------------------------
Sebelum melakukan *commit* atau pembagian kode ke repositori tim, periksa validitas
tipe data TypeScript pada frontend dengan menjalankan perintah:
  cd modellyng/frontend
  npm run typecheck

5. PANDUAN PEMECAHAN MASALAH: DUPLIKASI PAPER & PENAMAAN JUDUL
--------------------------------------------------------------------------------
- Masalah Peringatan "Isi dokumen identik dengan paper yang sudah ada":
  * Duplikasi dicek berbasis hash kriptografis SHA-256 per proyek riset (`project_id`).
  * Jika Anda menghapus proyek lama melalui tombol "Hapus Proyek", seluruh rekaman paper
    beserta file fisik otomatis terhapus secara tuntas, dan paper dapat diunggah kembali
    ke proyek baru tanpa batasan.
  * Catatan: Jika proyek sebelumnya hanya "Diarsipkan", proyek tersebut tetap tersimpan di tab
    "Diarsipkan". Gunakan tombol "Hapus Proyek" di menu kartu jika memang ingin membuangnya secara permanen.
  * Jika proses ekstraksi suatu paper sebelumnya sempat gagal (`failed`), sistem kini otomatis
    membersihkan rekaman gagal tersebut saat Anda mengunggah ulang file yang sama.
- Masalah Penamaan Judul PDF (Anti-Semrawut):
  * Pengunggahan file dengan nama acak (misal: `kudagoreng.pdf` atau `Cepat-Vol 5-No 1-pp1-8.pdf`)
    tidak akan lagi menghasilkan judul rusak seperti UUID atau metadata template jurnal.
  * Sistem menggunakan PyMuPDF font-size span heuristic seketika pada tahap upload, dan
    disempurnakan oleh model LLM pada Stage 5 Celery untuk memastikan judul ilmiah asli
    100% akurat diambil langsung dari isi dokumen akademik.

6. GRAF PENGETAHUAN TAMPIL SEBAGAI BEBERAPA KELOMPOK TERPISAH
--------------------------------------------------------------------------------
- Gejala: lencana pada kartu judul graf menampilkan "N kelompok terpisah", bukan "Terhubung utuh".
- Penyebab: graf dibangun dari matriks komparatif. Dua paper hanya dihubungkan bila ada simpul
  yang sama (identik) atau simpul sejenis dengan kata kunci bersama (garis putus-putus "Serupa antar paper").
  Paper yang topiknya tidak beririsan sama sekali tetap terpisah, karena relasi tidak dikarang.
- Langkah pemeriksaan:
  1. Buka simpul pada kelompok yang terpisah dan baca uraian serta bukti kutipannya.
  2. Pastikan paper tersebut memang membahas topik yang sama dengan paper lain dalam proyek.
  3. Bila topiknya berbeda, pisahkan paper ke proyek riset tersendiri.
- Lencana "N paper belum dianalisis" berarti ada paper berstatus memproses atau gagal. Paper tersebut
  baru tampil pada graf setelah statusnya Siap atau Perlu Tinjauan (tombol "Segarkan" memuat ulang data).

7. KUTIPAN BUKTI TIDAK MENYOROT TEKS PADA PDF
--------------------------------------------------------------------------------
- Hasil ekstraksi kadang mencatat halaman atau blok yang keliru untuk sebuah kutipan (misalnya blok yang
  hanya berisi satu kata). Penampil PDF memverifikasi blok tersebut terhadap teks kutipan, lalu mencari
  kutipan pada seluruh halaman dokumen (`relocateEvidence` pada `pdfMatcher.ts`).
- Bila kutipan tidak ditemukan pada halaman mana pun, penampil hanya membuka halaman yang tercatat tanpa
  sorotan. Perbaikan data dilakukan dengan memproses ulang paper dari ikhtisar proyek.

8. PANDUAN PENEGAKAN KUOTA LANGGANAN & TROUBLESHOOTING KUOTA
--------------------------------------------------------------------------------
- Batasan Tingkat Akun (Subscription Tiers):
  * Developer (admin@modellyng.ac.id): Tanpa batasan kuota upload (999.999 dokumen).
  * Student Pro 30 Hari (cahayu@modellyng.ac.id): Kuota 15 unggahan/ekstraksi dokumen per hari, akses penuh seluruh fitur analitik.
  * Free Plan (lawren@modellyng.ac.id): Batas 3 unggahan dokumen per hari (reset pukul 00:00 WIB), ukuran maks. 15 MB.

  * Seluruh mutasi kuota terekam di tabel audit `public.token_usage_logs`.
- Mengapa Muncul Pesan "Batas Kuota Harian Tercapai"?
  * Pengguna pada Free Plan telah mengunggah 3 dokumen dalam hari berjalan.
  * Kuota otomatis direset pada pukul 00:00 WIB (Asia/Jakarta). Pengguna dapat meningkatkan paket ke Student Pro melalui tautan WhatsApp admin di halaman `/settings/pricing`.
