BUKU PANDUAN OPERASIONAL & ARSITEKTUR SISTEM (MODELLYNG WEB)
Evidence-Centered Academic PDF Analysis Platform
================================================================================

dan mengembangkan seluruh ekosistem Modellyng Web (Frontend, Backend API,
Antrean Tugas Celery, Basis Data Supabase PostgreSQL, dan Redis).

PANDUAN INSTALASI & MENJALANKAN PROYEK PERTAMA KALI (CLONE DARI GITHUB)
================================================================================

Ikuti langkah-langkah di bawah ini secara runtut saat baru pertama kali menyalin
repositori ke komputer atau laptop:

--------------------------------------------------------------------------------
PRASYARAT PERANGKAT LUNAK (WAJIB TERPASANG)
--------------------------------------------------------------------------------
Pastikan aplikasi berikut sudah terpasang pada sistem operasi:
1. Git: Memeriksa instalasi di terminal -> `git --version`
2. Node.js (Versi 18 atau 20 LTS disarankan): Memeriksa instalasi -> `node -v`
3. Python (Versi 3.10 atau lebih baru): Memeriksa instalasi -> `python --version`
4. Docker Desktop: Pastikan aplikasi Docker Desktop sudah terpasang dan dalam status berjalan (*Engine running*).
5. Peramban Web Modern: Google Chrome, Microsoft Edge, Brave, atau Mozilla Firefox.


--------------------------------------------------------------------------------
LANGKAH 1: MENGUNDUH (CLONE) REPOSITORI DARI GITHUB
--------------------------------------------------------------------------------
1. Buka aplikasi Terminal (PowerShell, Command Prompt, atau Git Bash).
2. Jalankan perintah untuk mengunduh kode proyek:
   git clone https://github.com/Extluke/Modellying-web.git

3. Masuk ke folder utama proyek:
   cd Modellying-web


--------------------------------------------------------------------------------
LANGKAH 2: PENYIAPAN BERKAS KONFIGURASI ENVIRONMENT (.env)
--------------------------------------------------------------------------------
Layanan backend membutuhkan konfigurasi koneksi basis data, Redis, dan kunci API AI.

1. Periksa keberadaan berkas `modellyng/backend/.env`.
2. Jika belum ada, buat berkas baru dengan nama `.env` di folder `modellyng/backend/`.
3. Pastikan isi berkas tersebut memuat konfigurasi berikut:

   DATABASE_URL="postgresql://postgres:modellying_web_password@127.0.0.1:28022/postgres"
   REDIS_URL="redis://127.0.0.1:6381/0"
   CELERY_RESULT_BACKEND="redis://127.0.0.1:6381/1"
   GROQ_API_KEY="masukkan_groq_api_key_di_sini"
   GEMINI_API_KEY="masukkan_gemini_api_key_di_sini"

   *Keterangan Kunci API AI:*
   - Groq API Key dapat diperoleh secara gratis di: https://console.groq.com/keys
   - Gemini API Key dapat diperoleh secara gratis di: https://aistudio.google.com/app/apikey
   - *Catatan:* Jika kunci API AI belum diisi, sistem tetap dapat beroperasi normal menggunakan
     mekanisme ekstraksi kanonik PyMuPDF bawaan dengan bukti kutipan nyata.


--------------------------------------------------------------------------------
LANGKAH 3: MENJALANKAN BASIS DATA & CACHE (DOCKER SUPABASE & REDIS)
--------------------------------------------------------------------------------
Modellyng Web menggunakan konfigurasi kontainer Docker yang sepenuhnya terisolasi
(Domain `modellying-web`, Port Database `28022`, Port Redis `6381`).

1. Pastikan aplikasi Docker Desktop di komputer Anda sudah berstatus aktif (*Running*).
2. Di jendela terminal, masuk ke direktori docker backend:
   cd modellyng/backend/docker

3. Jalankan seluruh layanan kontainer di latar belakang:
   docker compose up -d

4. Tunggu beberapa saat hingga 5 kontainer aktif:
   - `modellying_web_db` (PostgreSQL Port 28022)
   - `modellying_web_redis` (Redis Port 6381)
   - `modellying_web_meta` (PostgreSQL Meta API Port 8080)
   - `modellying_web_studio` (Supabase Studio Web GUI Port 28023)
   - `modellying_web_inbucket` (Mailpit Email Sandbox Port 28024)

5. Verifikasi: Buka peramban web dan akses `http://localhost:28023`.
   Jika tampilan dasbor Supabase Studio terbuka, basis data telah siap digunakan.


--------------------------------------------------------------------------------
LANGKAH 4: MENYIAPKAN & MENJALANKAN BACKEND FASTAPI (TERMINAL 1)
--------------------------------------------------------------------------------
1. Buka jendela terminal baru atau kembali ke folder backend:
   cd modellyng/backend

2. Pasang seluruh dependensi Python yang dibutuhkan:
   pip install -r requirements.txt

   (Tunggu proses instalasi pustaka FastAPI, Uvicorn, PyMuPDF, Celery, Argon2, dll. selesai).

3. Jalankan server FastAPI:
   python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload

4. Verifikasi: Buka peramban web dan akses alamat:
   http://127.0.0.1:8000/docs
   Dokumentasi interaktif Swagger API akan muncul dan siap menerima permintaan.


--------------------------------------------------------------------------------
LANGKAH 5: MENJALANKAN PIPELINE EKSTRAKSI ASINKRON / CELERY WORKER (TERMINAL 2)
--------------------------------------------------------------------------------
Celery Worker bertugas memproses validasi berkas PDF, ekstraksi teks, segmentasi blok,
dan analisis 11 parameter ekstraksi di latar belakang.

1. Buka jendela terminal baru (Terminal ke-2).
2. Posisikan direktori kerja pada folder backend:
   cd modellyng/backend

3. Jalankan worker Celery:
   *Pada sistem operasi Windows, parameter `--pool=solo` wajib disertakan:*
   celery -A app.celery_app worker --loglevel=info --pool=solo

4. Verifikasi: Terminal akan menampilkan log koneksi ke broker Redis dan tanda siap:
   `[tasks] . app.pipeline.tasks.process_paper_pipeline`
   `celery@... ready.`


--------------------------------------------------------------------------------
LANGKAH 6: MENYIAPKAN & MENJALANKAN FRONTEND WEB (TERMINAL 3)
--------------------------------------------------------------------------------
1. Buka jendela terminal baru (Terminal ke-3).
2. Masuk ke direktori frontend aplikasi:
   cd modellyng/frontend

3. Pasang paket dependensi JavaScript/TypeScript:
   npm install

   (Tunggu hingga proses selesai dan seluruh pustaka React 19, Tailwind, serta Lucide terpasang).

4. Jalankan server pengembangan lokal (Vite Development Server):
   npm run dev

5. Terminal akan menampilkan informasi alamat server lokal:
   ➜  Local:   http://localhost:3000/


--------------------------------------------------------------------------------
LANGKAH 7: PENGUJIAN & AKSES APLIKASI DI PERAMBAN WEB
--------------------------------------------------------------------------------
1. Buka peramban web dan akses URL:
   http://localhost:3000/

2. Sistem secara otomatis akan mengarahkan rute awal ke halaman pembuka (`/welcome`).
3. Klik tombol "Masuk" untuk menuju halaman login (`/login`).
4. Gunakan salah satu akun uji coba siap pakai yang tercantum pada Bagian 4 dokumen ini.

================================================================================
DETAIL FITUR & INTEGRASI SISTEM
================================================================================

1. INTEGRASI FASTAPI & BASIS DATA SUPABASE POSTGRESQL
--------------------------------------------------------------------------------
- Backend menggunakan koneksi pool aman (`psycopg2-binary` dengan `ThreadedConnectionPool`).
- Seluruh registrasi akun baru dienkripsi menggunakan standar keamanan militer Argon2id.
- Skema tabel relasional meliputi:
  * `public.users`: Manajemen identitas, nama, email, dan hash sandi pengguna.
  * `public.projects`: Judul penelitian, rumusan masalah, bidang riset, dan format sitasi.
  * `public.papers`: Metadata dokumen PDF (judul, pengarang, tahun, hash SHA-256, jumlah halaman, dan status proses).
  * `public.extracted_components`: Hasil ekstraksi 11 parameter dalam format JSONB dinamis.
  * `public.paper_blocks`: Koordinat bounding box dan segmen teks per halaman untuk highlighter bukti PDF.
  * `public.password_reset_tokens`: Pengelolaan token unik pemulihan kata sandi dengan masa kedaluwarsa 1 jam.

2. FITUR RUANG KERJA PROYEK RISET & UNGGAH PDF
--------------------------------------------------------------------------------
- Halaman Proyek (http://localhost:3000/projects):
  * Pencarian instan judul/deskripsi dengan tombol bersihkan teks sekali klik.
  * Tab filter status: "Semua" dan "Diarsipkan".
  * Sistem pengurutan 5 kriteria: Terakhir Diperbarui, Tanggal Dibuat, Abjad (A-Z), Total Paper, dan Paper Siap (Ready).
  * Tombol pengalihan arah urutan: Naik (Ascending) dan Turun (Descending).
  * Kartu proyek interaktif dengan menu opsi: Edit, Arsipkan/Pulihkan, dan Hapus (kaskade).
  * Akses cepat: Mengklik area kartu proyek akan langsung membuka ruang kerja dokumen.
- Halaman Inisialisasi Riset (http://localhost:3000/projects/new):
  * Tampilan fokus bebas distraksi (tanpa bilah navigasi atas maupun bilah samping).
  * Judul resmi tunggal: "Inisialisasi Ruang Riset Baru" (terbebas dari penomoran langkah "1 dari 2" atau label non-profesional).
  * Formulir esensial dan bersih: Hanya menyisakan kolom Nama Proyek dan Deskripsi Ruang Riset.
  * Validasi nama proyek dalam Bahasa Indonesia yang santun ("Nama proyek minimal harus terdiri dari 2 karakter.") dengan notifikasi toast seragam durasi tepat 5 detik.
- Halaman Ruang Kerja Dokumen (http://localhost:3000/projects/:id/overview):
  * Judul seksi resmi dan bersih: "Dokumen Paper Ilmiah" tanpa embel-embel angka/hitungan pada teks judul.
  * Tombol aksi cepat: "Terima Semua Tinjauan" di sisi kanan judul seksi untuk menyelesaikan seluruh status tinjauan dokumen secara serentak.
  * Fitur pencarian paper instan dan pengurutan dinamis (berdasarkan Waktu Unggah, Abjad Judul, dan Jumlah Halaman dengan toggle Menaik / Menurun).
  * Desain kartu paper estetis dan profesional dengan penghapusan seluruh teks berbau jargon teknologi/model (bebas groq/llama/gatekeeper).
  * Indikator progres ekstraksi berupa progress bar bercahaya halus (glowing shimmer) lengkap dengan teks tahap aktif, menggantikan ikon jam statis.
  * Tombol pembuka asisten sintesis diberi nama profesional: "Tanya AI".
  * Modal Unggah PDF (`UploadPdfModal.tsx`): Desain elegan dengan backdrop blur mendalam (`backdrop-blur-md`), dropzone intuitif, dan pemantauan status unggah multi-berkas.

3. ISOLASI DATA MULTI-TENANT & NAVIGASI AKUN
--------------------------------------------------------------------------------
- Mekanisme Anti-Kebocoran Cache:
  Setiap kali pengguna melakukan pergantian akun atau keluar (*Logout*), seluruh cache
  in-memory TanStack Query langsung dibersihkan (`queryClient.clear()`).
- Pengikatan Kunci Kueri (Query Key Binding):
  Daftar proyek dan dokumen terikat secara ketat pada ID pengguna aktif (`userId`),
  memastikan data antar akun tidak pernah bercampur.
- Navigasi Otomatis Sesi:
  Setelah login berhasil, pengguna selalu diarahkan langsung ke Dasbor Utama (`/dashboard`).
  Akses ke halaman terlindungi otomatis dialihkan ke `/login` jika sesi belum terautentikasi.

4. PIPELINE EKSTRAKSI PDF ASINKRON (CELERY WORKER & REDIS)
--------------------------------------------------------------------------------
- Alur Pemrosesan 10 Tahap Idempoten:
  `queued` -> `downloading` -> `extracting_text` -> `quality_check` ->
  `doc_type_check` -> `saving_blocks` -> `ai_extraction` -> `verifying_evidence` ->
  `saving_ai_results` -> `ai_extraction_complete`.
- Validasi Magic Bytes:
  Memverifikasi penanda biner asli `%PDF-` untuk mencegah pengunggahan file rusak atau palsu.
- Deteksi Duplikasi Cerdas & Manajemen Berkas:
  Menggunakan enkripsi hash SHA-256 untuk mendeteksi dokumen identik dalam satu proyek (`duplicate_content`).
  Pesan error kini secara spesifik mencantumkan judul asli paper yang berkonflik.
  Jika paper yang pernah diunggah sebelumnya berstatus gagal (`failed`), sistem secara otomatis
  membersihkan entri lama dan mengizinkan pengunggahan ulang berkas yang sama tanpa terblokir.
  Penghapusan proyek (`DELETE /projects/:id`) membersihkan rekaman basis data (kaskade) serta
  seluruh file PDF fisik di dalam direktori `STORAGE_ROOT/{user_id}/{project_id}`.
- Ekstraksi Judul Asli & Penulis Paper Otomatis (Anti-Judul Semrawut):
  * Tahap Cepat saat Upload (Fast Heuristic): Fungsi `inspect_pdf_metadata` menyaring dan membuang
    metadata rusak bawaan template penerbit/Word (seperti `Author,+Information...`, `7952_2`, atau UUID).
    Sistem menganalisis ukuran font terbesar pada halaman pertama (excluding journal headers)
    sehingga judul asli langsung rapi sejak detik pertama diunggah, terbebas dari nama file sembarang.
  * Tahap Penyempurnaan AI (Stage 5 Celery): Model LLM (`openai/gpt-oss-120b`, `openai/gpt-oss-20b`,
    `qwen/qwen3.8-27b`) mengekstrak judul penelitian akademik yang bersih serta array nama pengarang
    (`authors`), lalu menyimpannya ke tabel `public.papers`.
- Arsitektur Abstraksi Model AI Terpadu (ModelRegistry — Gemini Core & Groq Backup):
  * Dual-Provider Resilient Architecture:
    1. Model Utama (Core Provider): Google Gemini (`models/gemini-3.5-flash`), dioptimalkan untuk sintesis ilmiah Bahasa Indonesia baku dan ekstraksi terstruktur.
    2. Model Cadangan (Backup Provider): Groq (`qwen/qwen3.8-27b` / `openai/gpt-oss-120b`), siap mengambil alih tugas seketika jika model utama mengalami kendala kuota.
  * Mekanisme Token Bucket Rate Limiting & Micro-Retry:
    - Pembatas laju independen sadar RPM dan TPM (`gemini_limiter` & `groq_limiter`) yang mencegah banjir request 429.
    - Micro-retry per model hingga maksimal 2 kali retry (total 3x percobaan per model) dengan jeda eksponensial (*exponential backoff* dan jitter).
    - Kegagalan total pada Core Model otomatis memicu pengalihan tugas (*seamless failover*) ke Backup Model tanpa memutus atau mengulang batch tugas yang sudah berhasil.
  * Validasi Skema Pydantic Ketat & Log Bersih (Sanitized Logging):
    - Seluruh respons LLM divalidasi secara ketat oleh skema Pydantic; data yang tidak lolos validasi tidak akan pernah masuk ke basis data.
    - Log sistem hanya mencatat metadata, model alias, dan waktu eksekusi; teks mentah naskah pengguna dilarang keras dicetak pada log.
- Gatekeeper LLM & Kebijakan Penerjemahan Baku (Indonesian First Extraction):
  * Mendeteksi apakah dokumen merupakan artikel ilmiah valid atau sekadar naskah non-paper.
  * System prompt mewajibkan seluruh nilai ekstraksi ilmiah (`value.text`) diterjemahkan dan diformulasikan ke dalam Bahasa Indonesia yang baku, elegan, dan akademis.
  * Kutipan bukti verbatim (`evidence.quote`) tetap dipertahankan dalam bahasa asli naskah PDF demi menjamin ketertelusuran fisik kanonik (*ground truth*).
- Sinkronisasi UI Cerdas (Smart Polling):
  TanStack Query pada frontend otomatis memantau status pemrosesan setiap 3 detik selama ada
  tugas aktif (`validating` / `processing`), dan otomatis berhenti saat status menjadi `ready` atau `needs_review`.

================================================================================
CATATAN TEKNIS & PEMECAHAN MASALAH (TROUBLESHOOTING)
================================================================================

1. PORT 3000 ATAU 8000 SEDANG DIGUNAKAN (PORT IN USE)
--------------------------------------------------------------------------------
- Jika port 3000 sedang terpakai oleh aplikasi lain, Vite secara otomatis akan berpindah
  ke port berikutnya (misalnya: `http://localhost:3001/`). Perhatikan alamat URL yang
  ditampilkan pada terminal.
- Jika port 8000 terpakai, Anda dapat menghentikan proses lama atau menentukan port lain
  pada perintah uvicorn dengan mengganti `--port 8000` menjadi `--port 8008`. Pastikan
  untuk menyesuaikan variabel `VITE_API_BASE_URL` di frontend jika mengubah port backend.

2. EKSEKUSI CELERY WORKER DI SISTEM OPERASI WINDOWS
--------------------------------------------------------------------------------
Sistem operasi Windows tidak mendukung mekanisme multiprocessing default Celery (fork).
Oleh karena itu, selalu gunakan argumen `--pool=solo`:
  celery -A app.celery_app worker --loglevel=info --pool=solo

3. DOCKER DESKTOP BELUM AKTIF ATAU GAGAL TERHUBUNG
--------------------------------------------------------------------------------
- Pastikan aplikasi Docker Desktop sudah dibuka sebelum menjalankan `docker compose up -d`.
- Jika kontainer gagal menyala karena konflik port, pastikan port `28022` dan `6381` tidak
  digunakan oleh aplikasi basis data lain di komputer Anda.
- Untuk mereset kontainer Docker ke kondisi bersih:
  cd modellyng/backend/docker
  docker compose down
  docker compose up -d

4. VERIFIKASI KETEPATAN TIPE DATA (TYPECHECK FRONTEND)
--------------------------------------------------------------------------------
Sebelum melakukan *commit* atau pembagian kode ke repositori tim, periksa validitas
tipe data TypeScript pada frontend dengan menjalankan perintah:
  cd modellyng/frontend
  npm run typecheck

5. PANDUAN PEMECAHAN MASALAH: DUPLIKASI PAPER & PENAMAAN JUDUL
--------------------------------------------------------------------------------
- Masalah Peringatan "Isi dokumen identik dengan paper yang sudah ada":
  * Duplikasi dicek berbasis hash kriptografis SHA-256 per proyek riset (`project_id`).
  * Jika Anda menghapus proyek lama melalui tombol "Hapus Proyek", seluruh rekaman paper
    beserta file fisik otomatis terhapus secara tuntas, dan paper dapat diunggah kembali
    ke proyek baru tanpa batasan.
  * Catatan: Jika proyek sebelumnya hanya "Diarsipkan", proyek tersebut tetap tersimpan di tab
    "Diarsipkan". Gunakan tombol "Hapus Proyek" di menu kartu jika memang ingin membuangnya secara permanen.
  * Jika proses ekstraksi suatu paper sebelumnya sempat gagal (`failed`), sistem kini otomatis
    membersihkan rekaman gagal tersebut saat Anda mengunggah ulang file yang sama.
- Masalah Penamaan Judul PDF (Anti-Semrawut):
  * Pengunggahan file dengan nama acak (misal: `kudagoreng.pdf` atau `Cepat-Vol 5-No 1-pp1-8.pdf`)
    tidak akan lagi menghasilkan judul rusak seperti UUID atau metadata template jurnal.
  * Sistem menggunakan PyMuPDF font-size span heuristic seketika pada tahap upload, dan
    disempurnakan oleh model LLM pada Stage 5 Celery untuk memastikan judul ilmiah asli
    100% akurat diambil langsung dari isi dokumen akademik.
